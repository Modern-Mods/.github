## About Modern Mods

**Modern Mods** is a Minecraft modding organization focused on building substantial gameplay systems for modern **NeoForge**.

Some projects bring beloved ideas from older Minecraft versions forward and rebuild them around current APIs. Others take familiar concepts and expand them far beyond their original scope. Some are completely new.

The common goal is simple:

> **Build mods that give players something meaningful to interact with, progress through, automate, customize, explore, or master.**

Our projects currently cover:

* Modular tool crafting and material progression
* Resource breeding and automation
* RPG companions and party systems
* Magic, combat, equipment, and character progression
* Procedural dimensions and large-scale exploration
* Machines and processing systems
* Mod interoperability
* Data-driven content
* Multiplayer-aware gameplay systems
* Extensible systems for modpacks and future content

Modern Mods is not focused on producing dozens of tiny isolated additions.

We like **systems**.

# Our Projects

## 🔨 Modern Tinkers

![Header](https://i.imgur.com/jc5Dp0F.png)

> **Build it from parts. Melt it. Cast it. Upgrade it.**

**Modern Tinkers** is a unified NeoForge bundle that ports and consolidates **Tinkers' Construct** and selected companion projects for Minecraft 1.21.1.

It brings modular tool construction, materials, smelteries, casting, modifiers, armor, shields, ranged equipment, crafting stations, alloys, fluids, world content, and progression into one modern project.

### Highlights

* Modular multi-part tools
* Material-dependent stats and behavior
* Tinker Station tool assembly
* Part Builder
* Modifier Worktable
* Melters
* Alloys
* Smelteries
* Casting tables and basins
* Molten materials and fluids
* Custom modifiers
* Armor and shields
* Arrows and ranged equipment
* Cobalt world generation
* Material-aware melting and casting
* Special tool interactions
* Server-authoritative crafting systems
* Consolidated content from multiple classic Tinkers ecosystem projects

### Current Status

Modern Tinkers has a **buildable NeoForge 1.21.1 port** with its major static registries and several core gameplay systems operational.

Current version:

`1.2.10`

Runtime validation, rendering work, multiplayer synchronization testing, optional integrations, and full gameplay parity remain ongoing.

## 🐔 Modern Chickens

![Header Image](https://i.imgur.com/VNccqK6.png)

**Modern Chickens** brings the classic **Chickens** and **Roost** resource automation loop into modern Minecraft while expanding it with dynamic resources, machines, fluids, chemicals, mod integrations, and extensive customization.

Players collect resource chickens, breed increasingly valuable lineages, improve their stats, place them into automation systems, and eventually build entire resource-production networks around them.

* Breeding trees and stat progression
* Roost automation

## 🏚️ The Labrinth

![Banner](https://i.imgur.com/ISs67HO.png)

> **There is no end. There is only another hallway.**

**The Labrinth** is an original NeoForge dimension project built around a simple idea:

### What if the maze was the world?

Instead of generating a traditional landscape, The Labrinth creates a world almost entirely from interconnected **interior spaces**.

Hallways lead into rooms.

Rooms lead into stairwells.

Stairwells lead onto different floors.

Forgotten doors lead into structures.

Structures lead deeper into the Labrinth.

And the world keeps generating around you.

### Highlights

* Procedural interior world generation
* Effectively enormous explorable layouts
* Deterministic generation
* Multi-floor environments
* Vertical connectivity
* Weighted corridor generation
* Variable room sizes
* Rare rooms
* Hidden passages
* Regional generation
* Depth-based progression
* Major landmarks
* Enclosed villages
* Multi-room dungeons
* Massive dungeon compounds
* Monster-controlled outposts
* Cave compounds
* Flooded areas
* Overgrown areas
* Ancient regions
* Industrial regions
* Corrupted regions
* Loot progression
* Environmental variation
* Structure ownership and reservation systems
* Debugging and structure-location tools
* Expandable room and structure architecture

The Labrinth is intentionally not a dungeon with a start and finish.

It is not a structure placed inside another world.

It is not a maze you are expected to solve.

**The dimension itself is the maze.**

Distance, depth, region, floor, rarity, neighboring structures, and generation conditions can all influence what the player discovers.

### Current Status

The Labrinth is in **early development**, but its core generation architecture is already substantial.

Implemented systems include deterministic generation cells, multi-story layouts, region selection, weighted corridors, procedural rooms, rare landmarks, villages, multiple dungeon scales, cave compounds, monster outposts, loot systems, depth calculations, and chunk-local structure ownership.

Future development will continue expanding custom blocks, entities, environmental hazards, ambient systems, dimension-specific resources, configuration, datapack support, multiplayer systems, and APIs for registering additional content.

# Development Philosophy

## Modern First

Legacy projects are references, not target implementations.

When bringing older concepts forward, we target modern **Minecraft 1.21.1 and NeoForge APIs directly** rather than trying to preserve obsolete architecture for its own sake.

---

## Preserve the Idea, Improve the System

A port should not lose what made the original project special.

At the same time, a modern version should be able to take advantage of:

* Modern registries
* Datapacks
* Tags
* Capabilities
* Components
* Current networking systems
* Modern world generation
* Current rendering APIs
* Better configuration
* Improved multiplayer architecture
* Modern compatibility APIs

Where it makes sense, our ports become expansions.

---

## Build for Modded Minecraft

Mods rarely exist alone.

Modern Mods projects are designed with interoperability in mind, including optional support for other mods without forcing unnecessary dependencies.

Depending on the project, this can include systems such as:

* JEI
* Jade
* WTHIT
* KubeJS
* Curios
* Sophisticated Backpacks
* Mekanism
* Ars Nouveau
* Iron's Spells 'n Spellbooks
* Epic Fight
* TacZ
* Other resource, magic, combat, and automation mods

Optional integrations should remain optional.

---

## Data-Driven Where Practical

Content that does not need to be hardcoded should be configurable or data-driven.

That can include:

* Recipes
* Loot
* Tags
* Materials
* Resource definitions
* Breeding relationships
* Structure metadata
* Generation weights
* Integration content
* Server configuration

This makes the mods easier to maintain and much more useful to modpack creators.

---

## Server-Aware

A feature working in a development client does not automatically mean it is finished.

Projects are developed with dedicated servers and multiplayer in mind.

Validation may include:

* Compilation and automated tests
* Client startup
* Dedicated-server startup
* Fresh-world testing
* Recipe and registry validation
* World generation testing
* Persistence testing
* Multiplayer synchronization
* Optional integration testing
* Upgrade and migration checks

# Contributing

Each project maintains its own source tree, references, technical requirements, validation process, and contribution rules.

Before contributing:

1. Read the project's `README.md`.
2. Read its `AGENTS.md` or contribution documentation when present.
3. Follow the repository's existing architecture.
4. Keep client-only code out of dedicated-server paths.
5. Test gameplay changes, not only compilation.
6. Preserve required licensing and attribution.
7. Document meaningful intentional differences from upstream reference projects.

Large ports should be treated as **behavioral adaptations**, not mechanical source merges.
