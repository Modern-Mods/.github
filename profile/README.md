## About Modern Mods

**Modern Mods** is a Minecraft modding organization focused on substantial gameplay systems, modern ports, expansions, and original projects.

Some of our projects bring beloved ideas from older Minecraft versions forward. Others take familiar concepts and build much larger systems around them. Some are completely new.

Our goal is simple:

> **Build mods that give players something meaningful to interact with, progress through, automate, customize, explore, or master.**

We like **systems**, interoperability, customization, and mods that can become a meaningful part of a larger modpack.

**Shared foundations. Modern mods.**

Hilt is the shared library and compatibility layer used by Modern Mods projects.

It provides reusable infrastructure for registration, data-driven content, materials, recipes, networking, fluids, utilities, interoperability, datagen, and other systems that would otherwise be duplicated between projects.

# Development Philosophy

### Modern First

Older projects are references, not frozen target implementations. Ports are adapted to modern Minecraft APIs and architecture rather than preserving obsolete systems purely for historical accuracy.

### Preserve the Idea, Improve the System

We want ports to retain what made the original project special while taking advantage of modern registries, datapacks, tags, configuration, networking, world generation, and interoperability.

Where it makes sense, a port can become an expansion.

### Build for Modded Minecraft

Our mods are designed to live alongside other mods.

Depending on the project, integrations may include:

`JEI` · `Jade` · `WTHIT` · `KubeJS` · `Curios` · `Mekanism` · `Applied Energistics 2` · `Refined Storage` · `Ars Nouveau` · `Iron's Spells 'n Spellbooks` · `Epic Fight` · `TacZ`

Optional integrations should remain optional whenever possible.

### Data-Driven Where Practical

Recipes, tags, materials, resources, breeding relationships, loot, structures, generation settings, and integrations should be configurable or data-driven when practical.

That makes our mods easier to maintain and much more useful to modpack creators.

Modern Mods projects are built with larger modpacks in mind.

* Datapacks
* Tags
* TOML configuration
* JSON recipes
* KubeJS
* Resource discovery
* Optional integrations
* Generation settings
* Custom registries and APIs

Check each project's repository for its currently supported customization systems.

# Contributing

Each project maintains its own technical requirements and contribution guidelines.

When contributing:

1. Read the project's `README.md` and contribution documentation.
2. Follow the existing architecture.
3. Keep client-only code out of dedicated-server paths.
4. Test gameplay changes, not only compilation.
5. Preserve required licenses and attribution.
6. Document meaningful intentional differences from upstream projects.
